# 偶鲸鲸桌宠助手合作分工

版本：1.0  
确认日期：2026年10月7日  
成员：A、B

## 共同目标

在现有 Windows 桌宠基础上，增加空间分析、DeepSeek 对话、笔记 RAG 和截屏提问，同时优化整体 UI 与动画。

所有能力共用一个轻量输入与输出区域。内部实现路径可以不同，用户在同一处获得文字、图表、引用、截图反馈和操作确认；默认展示简明结果，需要时在原区域展开细节。

产品向带工具调用能力的个人助手发展：模型可以选择范围明确的只读工具，查看结果后继续分析；移动、重命名、删除等文件修改必须获得用户逐次授权。

现有项目使用 C#、WPF 和 .NET 9，已有多角色桌宠、互动、设置、天气、番茄钟和待办。新功能在此基础上扩展，现有功能纳入回归检查。

## 成员 A 的功能范围

### 空间分析与文件操作

- 借鉴 WizTree 的空间占比展示，根据需求决定扫描文件夹或磁盘范围，不固定为某一个目录。
- 范围明确时，模型可以调用只读扫描；范围不清楚时，先让用户选择。
- 建议展示目录占比、大文件排行和可展开的面积图，明确占比分母与统计口径。
- 第一版不承诺达到 WizTree 的整盘扫描速度。扫描应可取消、展示进度；无权限或跳过的目录应可见，避免把不完整结果当作全盘结论。
- 文件大小与实际磁盘占用不同，界面需要标明使用的口径。
- 修改文件前列出具体路径、操作和影响，由用户逐次确认后执行；删除优先进入回收站。
- 模型可以提出处理建议，不能绕过确认自行修改文件。

### DeepSeek 简单对话

- 使用 DeepSeek 的 OpenAI 兼容接口，支持配置 API Key 和模型。
- 提供响应、等待、失败和重试等状态反馈。
- 当前会话保留上下文，关闭后不持久保存聊天记录；后续有需要再调整。
- Key 使用系统凭据保护，不写入代码仓库、日志或合作文档。

### 笔记 RAG 问答

目标是让用户向自己的笔记提问，获得带原文件和段落来源的回答，并通过实现过程学习 RAG。

流程：Markdown／TXT → 本地解析与分段 → 本地嵌入与索引 → 检索相关片段 → DeepSeek 生成回答 → 展示来源引用。

- 用户指定一个 Markdown 和 TXT 笔记空间。
- 笔记空间与磁盘扫描范围独立，不默认把扫描到的文件全部纳入知识库。
- 嵌入与检索在本地完成；问题、相关片段和使用到的当前会话上下文发送给 DeepSeek。
- 首次启用云端笔记问答时说明发送范围。本地检索不意味着全部内容不出本机，云端数据处理遵循服务商政策。
- 回答附带可打开的原文件及可定位的引用段落。
- 提供“查看本次检索片段”的入口，帮助区分检索问题与生成问题。
- 材料不足时明确说明，不凑出无依据的答案。
- 索引需要反映文件新增、修改和删除，初版可以手动刷新。
- 本地嵌入模型需另行选择，不能把接通聊天模型视为完成向量检索。

### 单次截屏提问

已确认采用单次触发，不要求用户手动截图后粘贴。

1. 用户点击一次“看屏幕”入口。
2. 助手暂时隐藏，避免把自身截入图片。
3. 用户框选区域。
4. 截图自动附加到当前输入区，无需经过剪贴板或手动粘贴。
5. 用户预览、输入问题并发送，也可以取消或重新截图。
6. 图片交给支持图像输入的 DeepSeek 模型，回答在同一区域展示。

默认不保存截图，不后台持续监控或定时上传。截图只代表采集时刻的画面，用户可以在发送前排除私人内容。

## 成员 B 的设计范围

重整桌宠、设置和助手的整体视觉与交互，保持轻量感。具体视觉风格通过设计稿共同确定，目前不预设最终美术方案。

- 优化字体、颜色、间距、控件和整体布局。
- 设计统一输入与输出体验，不另设多个独立功能窗口作为主要输出入口。
- 在同一输出区，根据结果类型展示流式文字、空间占比与排行、笔记引用、截图缩略图和操作确认卡片。
- 默认简明，细节可以在原区域展开。
- 覆盖等待、进度、取消、无结果、失败、重试和完成等状态。
- 优化角色动作、交互动画和界面过渡。
- 同步整合现有天气、番茄钟、待办和设置界面。

B 负责整体交互设计，而不只是更换配色或补动画；A 提供结构化数据与操作接口。

## 协作接口

双方先约定统一结果类型与状态，再分别开发。

| 类型 | 数据或交互 |
| --- | --- |
| 对话 | 流式文字与当前会话上下文 |
| 空间分析 | 扫描范围、统计口径、占比、大文件排行、进度和跳过目录 |
| 笔记问答 | 回答、文件路径、引用段落、本次检索片段 |
| 截图 | 图片附件、预览、取消、重截和图文提问 |
| 文件修改 | 目标路径、操作、影响、确认与执行结果 |
| 通用状态 | 进行中、完成、取消、失败与重试 |

A 负责数据与操作逻辑，B 负责布局与呈现。共同修改的窗口文件提前约定负责人，避免互相覆盖；授权与来源引用流程共同验收。

## 建议开发阶段

以下顺序为建议，不构成固定工期。每阶段双方同步联调，不等全部功能完成后再统一改 UI。

| 阶段 | A 的重点 | B 的重点 |
| --- | --- | --- |
| 一 | DeepSeek 对话、当前会话上下文、基础结果接口 | 统一入口和输出区原型、整体视觉方向 |
| 二 | 单次截图、自动附加、图文请求 | 截图预览、取消与重截、响应状态 |
| 三 | 按需扫描、空间统计、只读工具调用和修改授权 | 占比与排行、范围选择、确认卡片 |
| 四 | 笔记解析、嵌入与索引、检索、来源引用 | 笔记空间设置、引用展开和检索片段展示 |

## 验收标准

- **统一体验**：全部能力在同一交互区域输出，默认简明，细节可展开。
- **对话**：有效 Key 可进行对话；当前会话可承接上下文；关闭后不恢复历史；Key 不泄露到日志。
- **截图**：一次触发可框选并自动附加；取消不发送；无需手动粘贴；回答对应所选画面。
- **空间分析**：范围明确、口径可解释、扫描可取消、跳过目录可见；未经确认不能修改文件。
- **RAG**：只检索指定笔记空间；回答可回查原文；可查看检索片段；更新索引后反映文件变化。
- **回归**：换肤、拖动、散步、设置、天气、番茄钟和待办仍可用；新任务不阻塞桌宠交互。
